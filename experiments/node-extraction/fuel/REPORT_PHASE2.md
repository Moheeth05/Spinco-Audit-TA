## 3. Latency (decision 7)

Cold-cache run over 221 images, one policy after the other on the same machine (Intel i3-1005G1, 4 cores, 8 GB, CPU only, no network). Full table: `RESULTS_PHASE2.md`, `reports/retry-policy-comparison.md`, `reports/latency-investigation-*.json`.

* **Finding:** under the original retry, in the first 173-image measurement 47 of 57 retries gained nothing and cost ~176 of ~290 s; in the final 221-image comparison 65 of 76 gained nothing. The worst image took **33.5-38.7 s** across the two measurements (seven attempts, none useful), and **22 of 24 non-fuel controls were retried** though most had first-pass confidence of at least 0.8. Every retry that helped (11 images) started from first-pass confidence of 0.59 or lower, and was one 90-degree rotation or the production preprocessing.
* **Change (retry2):** skip when the first pass is confident (>= 0.7 and >= 30 characters); order attempts by what the first pass looks like (rotations first, preprocessing first only when the first pass was empty); stop at the first usable or confident attempt, after 4 attempts, or when a 12 s budget would be exceeded.
* **Result:** images retried 76 -> 38 (controls 22 -> 4); mean 1250 -> 705 ms; p95 3586 -> 2611 ms; **worst 33.5 -> 11.4 s**; total 276 -> 156 s. **Safety by a rule fixed beforehand:** image by image, no more false-confident fields, no more false accepts, no fewer true accepts, no fewer exact fields than the old policy, never worse than no retry at all; all 11 improvements preserved. 8 tests with a stub recognizer pin the policy. Residual: an 11 s worst case and 38 images still retried.

## 4. Defects found and fixed this phase (all generic; none hard-coded to a receipt)

Image-edge truncation (a name line cut by the image edge was accepted: now review); a printed label phrase left in the name (`Retail Outlet :`, `Dealer:`) generalised; `Fuel Station:` mistaken for a `Fuel:` product line; a brand heading with generic words (`Shell Select Station`) taken as the dealer; and, found while fixing, an over-greedy label regex that stripped `X STATION - City` names (a regression, reproduced by a failing unit test first). The earlier-found bill-number rule scope change is item 1 above.

## 7. Remaining limitations

1. No authentic Nayara, Jio-bp, Shell or unfamiliar-independent receipt; priority-brand behaviour is measured on synthetic receipts only.
2. Authentic labels unverified; n = 22 from 7 reports; all consumed.
3. No untouched evaluation set remains; new claims need new receipts (use `intake/`).
4. Synthetic receipts share one author and generator with the extractor: they measure robustness to what was imagined. The corrected labels now treat brand-only as not exact, but other label-design errors could remain.
5. OCR (tesseract.js) is still the main error source (dark/ghosted/rotated/large-print photos); retry2 helps but does not remove it; the extractor is deliberately conservative (authentic review rate 95%, 1/22 auto-accepted).
6. Unsupported wording/layout returns null + review: `Net Payable`, `Total Value`, column-header tables, dotted 2-digit-year dates, handwriting. No handwriting-accuracy claim is made.
7. The bill-number month rule rests on 7 family receipts (4 read by OCR) from 3 reports; it is family-specific and optional.
8. 11 s worst-case OCR latency remains; the browser-based review tool was smoke-tested in Edge only (one transient navigation error occurred once under CPU load and did not recur).
